# Project Hub Windows UI/UX 改版

日期：2026-10-11。沿用原生 HTML、CSS 與 JavaScript，未新增套件。

## 設計方向

這是日常操作 AI 作業的工作介面。設計以閱讀會話、辨認執行入口、提交需求為主要流程；作業設定與記事放在可展開區，保留原控制項及資料值。

| 項目 | 規格與用途 |
|---|---|
| 畫布／面板 | `#F7F8FA`／`#FFFFFF`，用細邊框分區 |
| 正文／次要文字 | `#111827`／`#475569` |
| 主操作 | `#1D4ED8`、白字；深色模式使用 `#A7BFFF`、`#111827` 字色 |
| 提醒 | `#92400E`，用於需注意的交接來源與狀態 |
| 字型 | Microsoft JhengHei、PingFang TC、Noto Sans TC、本機系統字型；沒有遠端字型載入 |
| 版面 | 桌面 256px 專案導覽、彈性會話區；900px 以下採手機收合導覽與輸入區 |
| 動態 | 按鈕色彩與原導覽過渡；尊重 reduced-motion |

## 已實作的互動

- 會話的主操作依入口顯示「交由 Codex 執行」或「準備手動交接」。選單分為本機執行、網頁手動交接、尚未就緒，手機保留網頁／未就緒提供者的完整身分。
- 網頁入口不顯示無適用意義的思考強度選單；原本的 API 值與入口檢查保留。
- 作業設定、記事、網頁交接捷徑可展開；同一頁面生命週期內，展開狀態依專案與作業保留。手機／桌面切換搬移同一份 DOM，保留輸入值。
- 手動交接在桌面呈現「準備內容／貼回保存」雙欄，手機變成單欄。交易狀態、復原、撤銷保留在進階展開區。
- 請求等待時顯示動作與「處理中」，設定 `aria-busy`，鎖住目的地及可編輯欄位，阻擋同一動作的重複請求；結束後恢復可操作控制項或狀態文字的焦點。
- 修改已預覽的需求會使舊預覽確認、複製、開站、保存失效，要求重新預覽。保留回答草稿及舊收據供查詢／復原；把文字改回原樣也不會復活核准權限。
- 手機導覽收起時使用 `inert` 與不可見樣式。展開時移入焦點、背景不接收焦點、Tab 在導覽與開關間循環；Esc 關閉並返回開啟按鈕。回到桌面時還原原先的 inert 值。
- 補上 Toast 的狀態宣告，以及手機訊息的提供者身分與來源提示換行。
- 發布前補上部分保存 HTTP 409 的顯示。API 仍丟出錯誤；只對 result／status／recover 路由且 actor、project、task、receiptId 與此次請求相符的未完成交易保留階段及目標狀態。顯示資料只含列舉值，不複製 Token 或原始回應到草稿。缺少可信結構時只提示「可能部分完成」，不猜測哪個檔案已保存。

## 執行與資料邊界

本次改動限前端、語系、測試與文件，沒有變更 API、Schema、授權或交易格式。Codex 仍依原核准流程；Claude／Agy／Grok CLI 尚未就緒時仍停用。ChatGPT／Claude Chat 維持人工登入、貼上、送出與貼回，不使用模型 API、不自動傳送、不把保存回答視為完成作業。草稿持久化仍不包含 preview 或 result 權限 Token。

## 驗證方式

```powershell
node --test --test-force-exit test/app-ui.test.js test/web-chat-ui.test.js test/i18n.test.js test/mobile-ui.test.js test/chat-scroll.test.js
```

以上檔案共 110 項測試，包含新增的入口身分、等待狀態、防重複操作、舊預覽拒絕與部分保存狀態測試。既有實際假 CLI／SSE 案例需本機檔案操作與 loopback，並保留其 45 秒工作區準備門檻。確切通過、逾時與重驗結果以本次交付報告及原始測試輸出為準。

瀏覽器驗證使用 `test/helpers/web-chat-browser-fixture.cjs`，專用合成 Root 與假 Codex。檢查桌面 1280×720、窄視窗 751×588 與手機 390×844／320×740、交接狀態、Tab／Esc、導覽切換及水平溢出；不據此宣稱真實提供者、正式資料或全部 Hub 功能完成驗收。

專案是 Node.js，沒有 Python `tests` 目錄。依使用者規範執行的 `python -m unittest discover -s tests -v` 會回報 `Start directory is not importable: 'tests'`，不是測試通過。
