# 完整自主開發與資安：具體驗收項目

更新：2026-10-19。依既有已核准設計及最新 Chat／CLI 範圍整理；本表沒有新增 OS、帳號、服務或隔離研究要求，也不是已完成清單。

## 產品與授權原則

產品是 Chat／CLI 多模型、多模組開發，從對話視窗接續同一任務，沒有 computer use。完整自主是：在已核准的任務、工作區、模型與工具範圍內，連續完成理解程式、改檔、命令、測試、修錯與交回成果。工作範圍內已授權的操作不重複詢問；跨出授權時保留原有具體核准流程。

CLI 原生工具、已註冊 MCP、子任務／委派均須能實際使用。不能將 CLI 限縮為僅文字回覆或產生 patch，卻宣稱 full-agent 整合完成。ChatGPT／Claude 網頁 Chat 維持人工交接；不以此宣稱外站網頁也可自動操作本機。

## 功能、安全控制與可重現驗收

| 項目 | 必須可用的自主功能 | 同時必須保留的安全控制 | 驗收例 |
|---|---|---|---|
| 程式與檔案 | 讀取／搜尋程式、依任務建立修改檔案、交回差異 | 工作區範圍、路徑與物件身分核對；供應秘密另有具體授權；既有使用者變更保留 | 在合成專案實際讀寫；未核准範圍外寫入拒絕，原檔不變 |
| 命令與測試 | 執行核准的建置、測試與開發命令，依真實輸出修錯 | 確切cwd/argv與工作授權；主機高權限、全域變更或新外部目的地不繼承一般專案授權 | 真實執行測試並辨識exit code；拒絕或啟動失敗不算測試成功 |
| 同對話續接 | 下一則指示延續原生session、需求、進度與成果 | project/task/actor/runtime/profile/session綁定；壞資料明確停止 | 第二回合修改第一回合產物，原生session與同一Hub task可核對 |
| 跨模型與多模組 | 切換模型／provider，委派子任務並回收結果 | 各provider session獨立；有來源的上下文交接；工作複本／互斥鎖避免互相覆寫 | A完成一個模組、B接下一模組，結果可追溯到同一父任務；不冒用A的session |
| MCP與工具 | 自主使用已核准註冊的工具／MCP，保留工具回應 | 設定來源與能力範圍受控；MCP token不能當owner，也不能核准自己；hooks／新增可執行設定須走既有審閱 | 實際已註冊工具呼叫成功；未註冊、跨task、過期與重放請求拒絕 |
| Queue與重新連線 | 保存待辦指示，斷線或重開UI後繼續原任務 | 不因UI重連重送已接受指示／重跑工具；執行中、已停與unknown分別呈現；資料錯誤不能當空狀態 | 重連後同request只執行一次；破損queue拒絕且原檔保留 |
| Stop與程序生命週期 | 在Hub停止當前run，保留對話與成果供續做 | 撤待核准操作；只停確認屬於本run的程序樹；取得退出證據後才回收；unknown保留鎖與資料 | 子程序亦退出；無證據不得顯示已清理；其他任務不受影響 |
| Git與交付 | 檢視diff、測試成果、依授權合併／提交，並安裝及回復版本 | 隔離工作複本、最新狀態與預覽核對；push／發布等符合具體授權；安裝來源／版本雜湊與可回復指標 | 實際安裝版完成工作流程；來源改變或過期合併預覽拒絕；失敗可回復舊版本 |
| 模型與成本 | 指定模型、顯示實際用量／錯誤；一般實作優先Sonnet | 明確指定模型與資料目的地，記錄實際回應版本；不默默升級Opus或更換provider | 核對實際模型；不可用就明示，不以另一個模型回答冒充 |

## 共同安全要求

- **憑證與資料傳輸**：Hub owner、CLI及MCP權限分開。未選取的秘密／其他provider登入檔不自動供應；所選內容會送往哪個模型服務須明示。CLI本體需要自身登入，不因此宣稱該憑證對同程序工具不可讀。
- **控制端存取**：維持既有登入、Host／Origin／CSRF、一次permit與到期／撤銷；loopback位置本身不能當作身分驗證。
- **供應來源與設定**：CLI／依賴版本與產物身分核對；不可信repo不能藉hooks、MCP設定或更新路徑取得額外權限。雜湊只辨識bytes，無簽章處如實揭露。
- **錯誤與證據**：破損、逾時、未知身分或未完成驗收均保留未確認狀態，不靜默bypass；只記必要資料，不把模型自述、fixture或本機log當成真實執行／外部認證。

## 已知限制與目前狀態

既有Codex已揭露：讀取不限task目錄，loopback仍可達；Hub的某些核准專案測試以owner使用者執行。Job object提供程序樹生命週期控制，不能當成任意CLI的檔案／網路沙箱。上述限制不能隱藏，也不能推論Claude／Grok已有相同保護。

Claude／Grok來源候選已接通正式Hub私有runtime、owner核准及一般工具政策；預設registry仍拒絕無私有authority的啟動，完整工具／MCP／委派及安裝版端到端尚未通過。已有codecs、turn controllers、兩個原生stdio adapter及歷史/session/queue資料錯誤處理，不構成本表整體通過。Claude與Grok各自的收窄合成兩回合、固定MCP及owned-tree退出已有真實驗證；Grok以第8次結果為準。歷史上首次Grok模型回合因認證鎖檔拒絕而未通過；第二次鎖定已取得、工具清單縮為指定4項，但CLI回報token到期及更新失敗，依授權中止，該次完整owned-tree回報未取得。保留各次不同的通過、失敗與清理證據。

使用者更新登入後，第3次在初始化階段被拒；第4次到達grok-4.6的read_file但串流輸入被誤判；第5次已讀檔與搜尋MCP，因未知RPC回應停止。第6次取得脫敏分類後，從官方來源及無認證／無模型的本機重現確認額外watcher回覆路徑；只處理兩個固定且精確的被動ACK，不接受任意未知ID。第7次實際處理1個skills ACK，取得一次owner核准並正確改檔，MCP則被我方測試核准器漏認variant=UseTool而誤拒。其修正、原生資料重放及實際產物的固定MCP驗證均已離線通過，原第7次失敗紀錄保留。

使用者另追加1次的第8次已通過：兩個獨占endpoint使用同一非空原生session，兩回合標記回憶、改檔、固定MCP均成功；每回合一次改檔及一次MCP owner核准，兩次exit0與完整owned-tree回報有效。原生工具清單仍為指定4項；限定私人技能標記檢查通過，不能當成完整TLS內容檢查。原出口與認證限制不變；148次連線被拒，未擴權。這次唯一一次額度已用完，沒有剩餘重跑授權。通用命令、完整委派、正式server與安裝版仍未驗證，未安裝。
