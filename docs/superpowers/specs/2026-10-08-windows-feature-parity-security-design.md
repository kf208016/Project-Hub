# Project Hub Windows 完整功能與資安設計

日期：2026-10-08。狀態：設計與實作計畫已核准，部分 Windows 能力已實作；完整原版功能尚未恢復。本規格保留設計時的證據與目標，最新實測進度以 `hub/WINDOWS.md` 為準。

修正：目前協作代理是 Codex。先前將 Claude 的原生 Windows 沙箱限制當成整個 Hub 必須採用 WSL2 的理由，推論過度；已撤回該前提。改以 Codex 原生 Windows 路徑優先，其他 CLI 個別驗證，原版功能保留的目標不變。

基準：上游 v4.68.2（031aedd4bf62ef4bb1e6199c31aa9c4323a116bb）。目前分支的 Windows 試作 commit 為 7349b2d1aad5e94adc5962a05eb4b83e2680d6e6。

## 需求與完成條件

使用者要求在 Windows 維持原版功能並兼顧資安。本輪已明確限定先完成原生 Codex 的全部 Hub 功能；Claude／Agy 保留待後續處理。前一版以停用功能降低風險，不能作為原生 Codex 範圍的完成品。

本規格以原版的使用流程與可完成的工作為基準：會話、終端機、AI 切換與委派、Git 工作複本與合併、非 Git 專案、設定檔供應、遠端、MCP、CLI 更新、圖片、整理還原、啟停都列入驗收。單純顯示按鈕、回傳固定拒絕、改成要求使用者在 Hub 外手動完成，均不算功能已恢復。

安全行為可以改變操作條件：例如首次信任專案、指定機密檔案、核准對主機的高權限操作、確認合併範圍。成功路徑須仍可在產品內完成，拒絕時須清楚說明缺少的權限與可行的恢復操作。

不保留上游無條件略過所有權限與沙箱的預設行為。若工作確實需要主機權限，必須顯示具體目標與影響並取得一次性授權；不能把「允許這個專案」解讀成永久管理員授權。

## 已確認的限制與證據

- 本機為 Windows Professional，build 26200；`wsl.exe --status` 回傳未安裝 WSL，exit 50。本次未安裝 WSL 或修改 Windows 功能。
- 本機存在 Codex npm 入口及 Claude npm 入口。Claude 2.1.252 的 npm 套件 `bin` 指向原生 `bin/claude.exe`，因此不能把所有 `.cmd` 一律當成 JS 入口。
- 本機 Codex CLI 為 0.154.0，`codex sandbox --help` 明列 Windows restricted-token 沙箱命令；`codex --help` 提供沙箱與審批參數。本次只執行說明命令，未變更全域設定或觸發沙箱安裝。
- Codex 官方支援原生 Windows 沙箱，優先模式為 `elevated`，`unelevated` 是較弱的備援模式。WSL2 不是 Codex 的必要條件。Hub 整合仍須確認實際採用的模式並驗證拒絕路徑，不能從本次 Codex 桌面會話推定另行啟動的 CLI 具有相同限制。[OpenAI 官方 Windows 沙箱文件](https://learn.chatgpt.com/docs/windows/windows-sandbox)
- Claude 官方目前明載：原生 Windows 的命令未受它的 OS 沙箱隔離；在 Windows 使用該沙箱需透過 WSL2。它的 shell 沙箱也不涵蓋所有檔案工具、MCP 與 hooks，因此僅加一個 CLI 旗標不足以形成完整主機隔離。[官方說明](https://code.claude.com/docs/en/sandboxing)
- 原版 `node-pty` 支援 Windows ConPTY，但以父程序權限執行；PTY 本身不是沙箱。[官方 README](https://github.com/microsoft/node-pty)
- 2026-10-08 以目前 lockfile 重跑官方 `npm audit --package-lock-only --omit=dev --json` 成功：已知弱點 0。此結果只涵蓋 lockfile 所列套件的資料庫檢查，不代表應用邏輯、套件原生二進位或執行環境無風險。
- 原版的 `ps/lsof`、`osascript/open/sips`、POSIX shell、MCP TOML 路徑、`.cmd` 執行與子程序生命週期需要平台實作；不能只移除 Windows 拒絕分支。

## 架構選擇

| 方案 | 功能與操作 | 資安邊界 | 維護成本與限制 |
|---|---|---|---|
| A：Windows 原生介面與 Codex（修正後優先方案） | 原生路徑與 Windows 工具；原版其他 CLI 各自接入平台 adapter | Codex 原生 Windows 沙箱、Hub 身分驗證與操作授權；不把 Codex 沙箱保證延伸到其他 CLI 或 Hub 自身 | 可先沿用已安裝的 Codex；其他 CLI 的隔離仍須個別設計與驗收，不能因此宣稱多 AI 已完整恢復 |
| B：按執行需求新增專用 WSL2 環境（選配） | 供 Linux 工具或需要該環境的 CLI 使用；不改變 Codex 原生路徑 | 額外 worker 的檔案、程序與網路邊界另行驗證 | 需新增 WSL2 與 Linux 維護；可能需要系統管理權限與重開機；有具體必要性時才提出 |

A 為修正後的優先方向，撤回「須先同意 WSL2 才能繼續」的要求。此修正不等於將產品縮減成只支援 Codex；Claude／Agy 等原版功能仍在驗收範圍，各自的安全能力不得混用。需要新增系統元件時，須先列出具體理由與影響。所有路徑仍須逐項驗證，沙箱或 WSL2 的存在本身不代表整體安全與相容已成立。

## 建議方案的信任邊界

1. **Windows 控制端**：提供瀏覽器／桌面介面、本機驗證、專案登錄、確認畫面、Git 主體更新、版本管理與記錄。以一般使用者權限執行。
2. **AI 執行端**：Codex 使用原生 Windows 沙箱並驗證實際生效模式；只授予此次工作的必要目錄與權限，不使用全域 bypass。沙箱失敗不得靜默改成無沙箱執行。其他 CLI、MCP 與 hooks 的程序權限須分別盤點，不能假設受到 Codex 保護。Hub 本身的 Git、更新與檔案操作仍需獨立授權及路徑驗證。
3. **工作通道**：固定、可驗證的請求格式；綁定專案、作業、run ID、允許路徑與到期時間。AI 使用的 MCP token 不能呼叫使用者核准、更新、安全設定或主機管理 API。
4. **網路**：模型服務及專案所需目的地主機採明確清單；新增目的地需核准。不可把禁用所有連線當成已保留完整功能，也不可把模型登入視為任意資料外傳授權。
5. **主機操作**：必須包含具體命令或檔案動作、目標、工作目錄、預覽內容的雜湊與有效期限。使用者核准後只消耗一次；參數或檔案狀態改變即重新預覽。AI 不能核准自己。
6. **威脅模型**：防範跨站請求、遠端未授權使用、惡意專案指令、路徑穿越、意外主機修改與錯誤機密傳遞。主機管理員惡意操作、核心／虛擬化漏洞、模型供應商帳號本身遭入侵不列為可由 Hub 完全防止的事項。

| 功能 | 恢復方式 | 主要驗收與拒絕案例 |

| 工具權限與需提高權限的工作 | 接入各 CLI 可用的權限協定；必要主機操作走具體核准 | 核准、拒絕、逾時、取消、範圍改變與重放；不能靠全域 bypass 讓測試通過 |

| 背景程序監測 | Windows 追蹤 run／PID／啟動時間及子程序樹；如需額外 worker 再加入對應監測 | 程序查詢失敗須顯示未取得，不能當作零程序；不以 PID 單獨識別重用程序 |
| MCP 讀取、報告與實作工具 | 正確 TOML 路徑；分離瀏覽器與 MCP 憑證，保留 work 開關 | 權限分層、跨專案拒絕、撤銷、到期、路徑穿越及 MCP 無法核准自身 |

| PNG/JPEG/WebP/GIF/HEIC、拖放與貼上 | 受控的本機轉換，保留原檔；GIF 保留原版首格行為 | 真實格式、大小／像素限制、破損輸入、轉換失敗不顯示已成功 |
| Windows 啟動、重新啟動、停止、桌面視窗 | 控制程序管理 CLI 子程序與服務生命週期；評估 WebView2 宿主完成原生檔案互動 | 關窗、Ctrl+C、崩潰、重新啟動、埠衝突、重複啟動；重新啟動不得遺失待處理工作 |
| 操作記錄與機密保護 | 必要寫入先確認記錄可寫；秘密遮罩、最小保留與 OS 權限 | 記錄失敗、磁碟滿及敏感輸出；本機紀錄不能宣稱外部不可竄改證據 |

## 實作次序與交付門檻

1. 保留目前試作為可回復基線，以 Codex 原生 Windows 能力驗證作為第一個技術門檻。
2. 建立平台 adapter、CLI 權限回應、登入／授權與程序生命週期；驗證工作目錄內成功、未授權寫入與網路請求遭拒、取消與逾時，以及沙箱不可用時停止。另行驗證機密與控制端 token 不向 AI 暴露。
3. 逐項恢復會話、終端機、Git、設定供應、MCP、遠端、更新、圖片及桌面行為，同步資料格式、文件與測試。
4. 整理上游測試的 POSIX fixture，保留原成功斷言並增加 Windows 真實 adapter 測試；不可把失敗測試直接跳過來取得全綠。
5. 使用非敏感測試專案驗證已安裝 CLI；第三方上傳、真正付費推論、實際遠端存取或更新使用者全域 CLI 前，呈現精確操作與影響。
6. 完成依賴／原生產物驗證、安裝／回復測試與功能對照。仍有固定停用、只有 mock 或未完成路徑時，不標示為「完整功能已恢復」。

原生方案先沿用 Windows 與 Codex，減少強制新增 Linux 的維護負擔。仍須維護各 CLI 協定、Windows 原生依賴與 Hub 自身安全控制；完整功能移植的排程需依第一個隔離／權限端到端驗證結果估計。
